# Dependency Rules

1. Canonical artifacts never import or name a runtime language, framework, package manager, SDK, or operating-system API.
2. Capability bodies depend on the external semantic-kernel contract and capability-local projected types only.
3. Capability bodies never import adapters.
4. Adapters implement declared ports and contain irreducible mechanics only.
5. Composition root is the only region allowed to seat adapters and capability packs.
6. Doorways invoke the composed query engine; they do not resolve authority or perform query semantics.
7. Capabilities compose through public contracts and semantic identities, never private file paths.
8. Migration assets are evidence until an admission record promotes a specific canonical asset.
9. Evidence and reports are generated outputs and never authority.
